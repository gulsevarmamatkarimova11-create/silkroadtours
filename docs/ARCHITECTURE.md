# Silk Road Tours — Phase 1: System Architecture

## 1. Stack decisions

| Concern | Choice | Why |
|---|---|---|
| Framework | **Next.js 15 (App Router)** | Server components for SEO-heavy destination/tour pages, route handlers for the API, one codebase for site + admin. |
| Cloudflare adapter | **`@opennextjs/cloudflare` → Workers + Static Assets** | `@cloudflare/next-on-pages` is deprecated. OpenNext runs on the Node-compatible Workers runtime (`nodejs_compat`), so there are no edge-runtime restrictions. GitHub CI/CD runs through Workers Builds or `wrangler-action`. |
| Database | **Cloudflare D1 + Drizzle ORM** | Native binding, so no connection strings, no pooling and no extra vendor. Drizzle generates SQL migrations that `wrangler d1 migrations apply` runs. |
| Auth | **Own session auth**: PBKDF2-SHA256 (Web Crypto, 100k iterations, the Workers maximum) plus a hashed session token in D1 and an HttpOnly cookie | No third-party auth dependency for a small admin team. The first owner is created with `ADMIN_SECRET`. |
| Anti-spam | **Cloudflare Turnstile** on all public forms, plus per-IP-hash throttling | Bookings trigger Telegram alerts, so bot submissions must be blocked. |
| i18n | **next-intl**, `/en`, `/uz`, `/ru` prefixed routes | UI strings live in `messages/*.json`. DB content is stored as `{en,uz,ru}` JSON columns with English fallback. |
| Currency | Pure pricing engine (`src/lib/pricing.ts`), rates in `settings` | Each tour has a base currency. Per-tier USD/UZS/EUR overrides are optional. Rates are editable in the admin, with a one-click refresh from the Central Bank of Uzbekistan (cbu.uz) JSON feed. |
| UI | Tailwind CSS v4, Lucide, Framer Motion, React Hook Form + Zod, Leaflet + OpenStreetMap | Leaflet with OSM tiles needs no API key, which keeps maps zero-config. |
| Media | Absolute URLs (R2 public bucket or any CDN), `images.unoptimized` | Next's image optimizer isn't available on Workers. An R2 upload endpoint can be added in Phase 4. |

## 3. Data model

```
destinations 1───* tours (primary_destination_id)
destinations *───* tours   via tour_destinations (multi-city routes)
tours 1───* tour_itinerary_days
tours 1───* tour_price_tiers      (group|private × pax range × USD/UZS/EUR)
tours 1───* tour_departures       (dates, seats, ±% modifier, status)
tours 1───* reviews  *───1 destinations
tours 1───* bookings *───1 tour_departures
bookings 1───* booking_notes      (notes + status audit trail) *───1 admin_users
service_requests                  (transfer | custom_tour | accommodation | guide, JSON payload)
faq_items, settings (exchange_rates, contact), admin_users 1───* admin_sessions, login_attempts
```

Key rules:
- **Money** is stored in integer minor units (cents; whole so'm for UZS). Every booking stores both the quoted total in the customer's currency and a USD-cents figure, so revenue analytics work across currencies.
- **Pricing resolution**: find the tier for (booking type, adults + children). The per-person price uses the tier's explicit price in the chosen currency if set, otherwise the base-currency price converted at current rates and rounded ($1 / €1 / 1,000 so'm). Then the departure ±% modifier applies. Children pay `child_price_percent` of the adult price.
- **The server quote is authoritative.** The client card uses the same `quote()` function, but `/api/bookings` recomputes the quote before saving.
- **Bookings snapshot** the tour title, so they stay readable after the tour is edited or deleted (`ON DELETE SET NULL`).
- **Reference IDs** look like `UZ-2026-48392` (5 random digits, which is safer than 4 at volume). They're unique-indexed, and the insert retries on collision. The year is taken in Tashkent time.
- **Privacy**: no raw IPs are stored. Each IP is hashed with SHA-256 (keyed by `SESSION_SECRET`) and used only for throttling.

## 4. API endpoints

All responses are JSON: `{ data }` on success, `{ error: { code, fields? } }` on failure. Inputs are validated with the Zod schemas in `src/validators`.

### Public

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/tours?audience&destination&category&month&guests&q&sort&page&currency` | Filtered listing with "from" price in the chosen currency |
| GET | `/api/tours/[slug]` | Full tour (itinerary, tiers, upcoming departures, reviews summary) |
| GET | `/api/tours/[slug]/quote?adults&children&type&currency&departureId` | Live price for the sticky booking card |
| GET | `/api/destinations` · `/api/destinations/[slug]` | Directory and landing-page data, with linked tours |
| GET | `/api/reviews?tour&destination&limit` | Published reviews + average |
| POST | `/api/reviews` | Guest review of a completed booking (reference + email), held for moderation |
| GET | `/api/contact` | Agency name, phone, messengers, address |
| GET | `/api/faq?category` | Travel guide FAQ |
| GET | `/api/rates` | Current exchange rates (edge-cached for 10 min) |
| POST | `/api/bookings` | Turnstile → validate → quote → insert PENDING → Telegram alert → `{ reference }` |
| GET | `/api/bookings/[reference]` | Confirmation view (tour, date, pax, status only; no personal data) |
| POST | `/api/service-requests` | Transfer / tailor-made / accommodation / guide → insert → Telegram alert |

### Admin (HttpOnly session cookie; mutations also check `Origin`)

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/admin/auth/bootstrap` | Create the first owner (requires `ADMIN_SECRET`; works only while no admins exist) |
| POST | `/api/admin/auth/login` · `/logout` · GET `/me` | Session lifecycle, with login throttling |
| POST | `/api/admin/auth/password` | Change own password (signs out other sessions) |
| GET / POST · PATCH | `/api/admin/users[/id]` | Owners manage admin accounts (last owner protected) |
| GET | `/api/admin/stats?from&to` | Totals, revenue estimate (USD), status funnel, top destinations, inbound/domestic ratio, daily series |
| GET | `/api/admin/bookings?status&audience&q&from&to&page` | Filtered list |
| GET / PATCH | `/api/admin/bookings/[id]` | Detail; status change (writes an audit note and adjusts departure seats) |
| POST | `/api/admin/bookings/[id]/notes` | Internal note |
| POST | `/api/admin/bookings/[id]/notify` · `/api/admin/service-requests/[id]/notify` | Resend the Telegram alert |
| GET / PATCH | `/api/admin/service-requests[/id]` | List and update status/notes |
| GET / POST | `/api/admin/tours` | List / create |
| GET / PUT / DELETE | `/api/admin/tours/[id]` | Edit / delete (blocked if bookings exist; the tour is unpublished instead) |
| POST | `/api/admin/tours/[id]/duplicate` | Deep copy (itinerary, tiers) as an unpublished draft, `slug-copy` |
| PUT | `/api/admin/tours/[id]/itinerary` · `/pricing` | Atomic replace (D1 batch) |
| POST / PATCH / DELETE | `/api/admin/tours/[id]/departures[/depId]` | Manage dates |
| CRUD | `/api/admin/destinations`, `/api/admin/faq` | CMS |
| GET / POST · PATCH / DELETE | `/api/admin/reviews[/id]` | Moderation (recomputes the tour rating); add real Google/TripAdvisor reviews with a source link |
| GET / PUT | `/api/admin/settings/[key]` | Contact info, exchange rates |
| POST | `/api/admin/settings/rates/refresh` | Pull USD/EUR rates from cbu.uz |
| POST | `/api/admin/settings/telegram/test` | Send a test message to the bookings group |

## 6. Visual direction (applied in Phase 3)

- **Palette:** terracotta `#B5532E`, desert sand `#E9D8B8`, lapis `#1F3A93` (deep `#14235C`), turquoise tile accent `#2A9D8F` used sparingly, off-white `#FAF6EF`, ink `#1E1A16`.
- **Type:** a display serif with character for headings (e.g. Fraunces) and a clean humanist sans for body text (e.g. Inter Tight). Both support Cyrillic and Uzbek Latin `oʻ gʻ`.
- **Motifs:** girih/ganch geometric patterns as thin line ornaments and section dividers, and arched (iwan-shaped) image masks.
- **Motion:** slow fade/rise on scroll, parallax only on the hero, and `prefers-reduced-motion` respected.
